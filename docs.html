01 / Read first

Before you start

PauzeControl is under active development. Features may be incomplete, and test builds may not be suitable for general use.

  • Use only an app build shared through your approved testing channel.
  • Keep the Mac-side app and Android companion on compatible builds.
  • Check the app repository's current notes for known issues before testing.
  • Back up important files before testing file transfer functionality.
Public downloads are intentionally not offered by this website while release approval is pending.

02 / Connection

Pairing overview

The current design uses a Mac-side agent and an Android companion that communicate over a direct device connection. This public website is not a pairing service and does not proxy your local session.

  1. Launch the Mac-side agent and Android companion from the test build you were given.
  2. Use the pairing flow shown in that build. Confirm that the host details refer to your own Mac.
  3. Allow the devices to connect on the network required by the app configuration.
  4. Test one function at a time and check each device for permission prompts or visible errors.
Pairing labels and exact steps may change as development continues. Follow the instructions displayed by your build if they differ from this overview.
03 / System access

Permissions and privacy

Some Mac features depend on macOS privacy permissions. Grant only the access required by the capability you are testing, and review the operating system's explanation before approving it.

  • Screen capture: live screen viewing may require screen-recording access.
  • Remote keyboard and pointer: input-control behaviour may require Accessibility or Input Monitoring permission, depending on the current implementation.
  • Network access: local firewall or network settings can affect whether the devices can find each other.

The website itself does not collect Mac screen contents, local files, audio, or private device-session telemetry.

04 / File handling

Testing file transfers safely

  • Begin with a small, non-sensitive test file.
  • Confirm that the saved filename and file size match the original.
  • Test empty files separately from normal files.
  • If a transfer is interrupted, confirm the receiving file is not mistaken for a completed transfer.
  • Avoid confidential data in development builds and bug reports.

File transfer is still in testing. Keep a separate copy of anything important until your test build has been validated.

05 / Troubleshooting

When something does not work

  • Confirm both devices are on a compatible test build and the intended network.
  • Review macOS permissions and any error message shown in the app.
  • Restart the feature or reconnect the devices, then note whether the problem repeats.
  • For audio/video timing issues, include the Android device model and the actions that cause the offset.
  • Do not post pairing secrets, access tokens, private addresses, or sensitive files in public issues.
06 / Improve the app

Report a bug with useful detail

Include the app build, macOS version, Android version, device models, repeatable steps, expected behaviour, actual behaviour, and redacted logs where relevant. Do not include passwords, access tokens, or other secrets.
